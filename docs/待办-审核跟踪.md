## 本轮：并列排名 + 隐藏首查（2026-10-05 落地）

- **口径**（维护者定）：**名次键**决定名次 —— 深渊 层→星、剧诗 模式→幕→星章→用时、危战 难度→用时；星铁 末日 难度→分、虚构 层→星→分→轮、忘却 层→星→轮、仲裁 绝境→王棋→骑士→轮。`战斗` / `借出` **移出名次键，只展示**（这类字段会随重复挑战变差，进名次会让排名往回走）
- **并列**：名次键相同 ⇒ 同编码 ⇒ **密集名次**（1,1,2）；组内按**首查**先后。本人名次按「严格更好的不同编码个数 + 1」，所以并列者与列表同名次
- **首查**：该期**第一次观测到成绩**的时刻，**冻结不刷新**（撤销 `a766496` 的「层/星上升即刷新」）、**不展示、不进分数**
- **取值**：名次键取**本期最优**（更差的上报不覆盖），只展示的字段取**最后一次观测**
- **实现**：`rankKeyScore`（混合进制折叠，块宽 = 上界 + 1）取代 `compoundScore`；`getRank` 改为「分数降序 + 同分按首查」的密集名次；`getRankForUid` 改为数不同编码；星铁侧新增 `firstTime` 记录与重排支持；`modules/challenge/gsRank.js` 去掉首查列（榜单少一列）
- **顺带修掉**：星铁虚构旧编码 `score×10` 在分数 ≥ 10000 时会借位顶掉星数位（块宽不够）
- **回归**：`test/rank-order.test.mjs` 14 → **38 条**（含星铁侧）；负向验证：临时还原「密集名次」「同分按首查排序」→ 3 条转红，还原后 SHA256 一致
- **#4 争议 1 收口**：「首查按首个 vs 分数按最后」的口径已由本轮定死（名次键只变好 / 展示取最后 / 首查冻结）；#4 剩余的「元信息与 ZSET 不一致」并发收口与**锁粒度**已由**批 D** 定死（见下节）
- **部署后必须**执行一次 `#刷新…排行` / `*刷新…排行`：编码口径变了，旧 ZSET 里仍是旧编码。星铁老数据没有 `firstTime`，重排后并列组内会排在同名次末尾
