# 模块：圣遗物总榜 / 遗器总榜（miao 群排行摊平）

本文件是 Axiu-Plugin 的详细文档。**规范与铁律在仓库根 `AGENTS.md`**；这里放事实与实现细节。

## 功能

把 **miao-plugin 的群排行**（`mark` = 圣遗物/遗器评分）摊平成一张榜：**不指定角色**，一行 = `(uid, 角色, 分数)`；
同角色多 uid、同 uid 多角色**都会各占一行**（不去重），按分数降序取前 N。

伤害榜（`dmg`）不参与：不同角色的伤害没有统一标准，无法排序。

## 命令

| 命令 | 权限 | 说明 |
|------|------|------|
| `#圣遗物总榜` / `#遗器总榜` | all | 本群总榜（原神 / 星铁，按前缀判定游戏） |
| `*遗器总榜` | all | 星铁本群总榜（框架把 `*` 归一成 `#星铁`，即 `#星铁遗器总榜`） |
| `#全局圣遗物总榜` / `#全局遗器总榜` | all | 全局总榜（跨群，键里的群号即来源群） |
| `*全局遗器总榜` | all | 星铁全局总榜 |

- 两条 rule（本群 / 全局）共用一个 `fnc`：`apps/artisRank.js → artisRank()`
- 本群总榜**仅群聊**；全局总榜私聊也能用（不依赖当前群）
- `priority: 1`（与 `apps/challenge.js` 的排行命令同级，先于 miao 的群排行命令匹配）

## 数据来源（只读 miao 的 Redis 键）

| 键 | 类型 | 内容 |
|----|------|------|
| `miao:rank:{groupId}:mark:{charId}` | ZSET | member = uid，score = 评分（本模块**唯一**读取的排行键） |
| `miao:rank:{groupId}:cfg` | String JSON | `status === 1` = 本群**已关闭**群排名 |
| `miao:rank:uid-info:{uid}` | String JSON | `{qq, uidType}`，uid → QQ |

键格式与角色 id 形态对齐 miao 的 `models/ProfileRank.js`：
**原神角色 id 8 位、星铁 4 位**（`getCharacterFromKey` 的正则），群号为数字。键里的 `charId` 位数决定游戏，
所以原神榜与星铁榜靠同一套键、按位数过滤。

**残留容忍**：miao 的 `apps/profile/ProfileRank.js → refreshRank()` 以 `{groupId, game}` 对象调用
`models/ProfileRank.js → resetRank(groupId, charId, game)` 的位置参数，那次「重置」实际是空操作，
ZSET 里可能留下已退群/已删角色的旧条目。本模块**照常读出来显示**（角色名兜底成 `未知角色(charId)`），
**不做清理**（清理是上游的事，本插件不碰 miao 的写路径）。

## 口径

| 项 | 口径 |
|----|------|
| 范围 | 本群 = `redis.keys('miao:rank:{群号}:mark:*')`；全局 = `redis.keys('miao:rank:*:mark:*')`，群号从键里解析 |
| 行 | 一行 = (uid, 角色, 分数)；同角色多 uid、同 uid 多角色各占一行 |
| 排序 | 分数降序；同分按 `uid → charId → groupId` 升序（保证同一份数据每次结果一致） |
| 名次 | 按位置连续编号 1..N（同分不去重、不并列），前 3 名在模板里有单独样式 |
| 人数 N | miao 的「排行人数」配置 `Cfg.get('rankNumber', 15)`；取不到或非法时兜底 **15** |
| 取数 | **每个键只取前 N 条**（`zRangeWithScores(key, -N, -1)`）——汇总榜的前 N 不可能来自某角色第 N 名之后 |
| 性能 | 键数 > 300 时按 50 个一批 `await`（分批并发），避免一次并发几百个 Redis 请求 |
| 身份 | uid → qq 读 `miao:rank:uid-info:{uid}`；本群优先 `e.group.pickMember(qq)` 的群名片/群头像，取不到回落 `用户:{qq}` + `https://q.qlogo.cn/g?b=qq&nk={qq}&s=100`（与 `modules/challenge/gsRank.js` 同口径），无 uid-info 时昵称 `未知用户`、头像留空 |
| 角色展示 | `Character.get(charId, game)` 取角色名 / `imgs.face` / 星级；头像拼 miao 的 `resources` 绝对路径前缀（只读它的静态资源） |

## 渲染

- 模板：`resources/artisRank/rank.html` + `rank.css`（**方案 B：自建布局，不复刻 miao 的面板卡模板**）
- 继承 `resources/common/layout/default.html`，页脚版权行由 `components/render.js` 注入 `sys.copyright`
- 调用：`render('artisRank', 'rank', data, 'jpeg')`，回复用 `e.reply(图片段)`（不自拼 base64）
- 渲染数据：`{title（圣遗物总榜/遗器总榜）, scopeText（本群/全局）, showGid（全局时显示来源群号）, topN, count, list, faceBase}`

## 降级与提示（都不出图）

| 情况 | 回复 |
|------|------|
| 本群已关闭群排名（`cfg.status === 1`） | `本群已关闭群排名，群管理员或 Bot 主人可通过【#启用排名】启用` |
| 该范围没有任何 mark 键 | `暂无排行数据：请先在群内用 #面板 / *面板 查看过角色面板` |
| miao 缺失 / 模块结构变化（懒加载失败） | `该功能需要 miao-plugin`（同时 `logger.warn`） |
| 私聊用本群总榜 | `总榜功能仅限群聊使用` |

判断顺序：**群开关 → miao 可用 → 有没有数据**（关闭群不因 miao 缺失而改变提示）。

### 跨插件依赖约定

- **不允许** `import ... from '#miao'`（该别名只在 miao 包内生效），一律**相对路径**动态 `import`：
  `../../miao-plugin/components/index.js`（`Cfg`）、`../../miao-plugin/models/index.js`（`Character`）、
  `../../miao-plugin/apps/profile/ProfileRank.js`（`refreshRank`）
- 一律「懒加载 + try/catch」，失败降级成提示，不影响插件其他功能
- **不修改 miao-plugin 的任何文件**，只读它的模块与静态资源

## 排行榜定时刷新

`apps/rankRefresh.js`（定时任务，默认**关闭**）：

1. **Axiu 侧**：`model/gsChallengeRank.js` 与 `model/srChallengeRank.js` 的 `rebuildAll()`（各自带重置锁，单套失败不影响另一套）
2. **miao 侧**：先 `redis.keys('miao:rank:*:mark:*')` 解析出**有排行数据的群集合**（不遍历机器人所在的所有群），
   逐群 × `{gs, sr}` 合成最小事件对象后调 miao 的 `refreshRank(e)`：
   `{ group_id, group: Bot.pickGroup(gid), isSr, isMaster: true, reply: async () => {}, runtime: {} }`；
   群与群之间 `delay 300ms`（miao 侧要逐个 uid 拉面板），**单群失败不中断**，记下失败群与原因
3. **汇总**：`notifyMaster` 为真时私聊 Bot 主人（刷新群数 / 失败群 / Axiu 侧重排结果 / 耗时 + 版权行）
4. miao 缺失或 `refreshRank` 签名变化 → `logger.warn` + 只刷 Axiu 侧，汇总里写明

配置（`config/config.yaml` → `rankRefresh:` 段，锅巴「阿修插件 → 排行榜定时刷新」可视化配置）：

| 配置项 | 默认 | 说明 |
|--------|------|------|
| `rankRefresh.enabled` | `false` | 关闭时任务仍注册，进入后立即返回（**零 Redis 访问**）；避免开箱就全群跑重活 |
| `rankRefresh.schedule` | `"0 40 4 * * ? *"` | Quartz 表达式（支持秒），即每天 4:40；同步到 Y 盘/服务器后需重启生效 |
| `rankRefresh.notifyMaster` | `true` | 刷新完成后私聊 Bot 主人一条汇总 |

## Redis 键（本插件自己写的）

**无**。本模块只读 miao 的键；定时刷新调用 miao 的 `refreshRank`，写的是 miao 自己的键。
