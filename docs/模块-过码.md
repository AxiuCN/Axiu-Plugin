# 模块：米游社过码

本文件是 Axiu-Plugin 的详细文档。**规范与铁律在仓库根 `AGENTS.md`**（约定、配置写入口径、测试约定）；这里放事实与实现细节，改对应模块前按需阅读。

### 3. captchaHandler — 米游社过码

- 事件：`mys.req.err`（namespace: `Axiu-Plugin`，key: `mys.req.err`），通过 `handler[]` 注册
- `const loveMys = new LoveMys()` 在 `captchaHandler.js` 模块顶层创建单例，`LoveMys` 构造函数无参数、无实例状态，所有方法通过参数接收上下文
- 仅处理 retcode 1034/10035（Geetest 验证码），其他错误调用 `reject()` 放行
- 两种模式：
  - **`OnlyGtest`**：仅求解验证码，不重放请求（供其他插件使用）
  - **默认**：求解验证码 → 重放原请求（带 `x-rpc-challenge` header）
- 配置校验：根据 `api.type` 检查必填字段（`captchaHandler.js` `mysReqErrHandler`），校验失败则 `reject('未正确填写配置文件')`

| `api.type` | 平台 | 必填字段 |
|-----------|------|---------|
| 0 | test_nine（本地 AI） | `api`（本地服务地址） |
| 1 | ttocr.com | `api`, `resapi`, `key`, `query` |
| 2 | 2captcha.com | `api`, `resapi`, `key`, `query`, `resquery` |

> 仅当 `GtestType` 为 1（仅自动）或 2（自动优先）时才校验。`GtestType=0`（仅手动）时跳过自动平台校验。

#### 过码链路（model/loveMys.js）

```
mys.req.err(1034/10035)
  → getvali() → mysApi.getData() → retcode≠0 → geetest()
    → getDeviceFp.Fp() 获取设备指纹
    → mysApi 创建 Geetest 挑战（createGeetest/createVerification）
    → 根据 api.type 求解：
      type 0: test_nine 求解+验证，失败重试最多3次（每次重新创建挑战）
      type 1: ttocr.com recognize→轮询results（最多10次，间隔5s）
      type 2: 2captcha.com in→轮询res（最多10次，间隔5s）
    → 求解成功 → verifyGeetest/verifyVerification（verify 成功后直接 return）
    → 求解失败 + GtestType=2 → Manual_geetest 手动打码
      → 发送验证链接给用户 → 轮询结果（最多80次，间隔1.5s=2分钟）
  → 重放原请求（x-rpc-challenge header）
```

> **UID → Server 判定**（`mysApi.getServer()`）：根据 UID 前缀确定米游社服务器，影响 API 域名（CN vs 海外）、DS 签名盐值、设备指纹参数。
>
> | 游戏 | 前缀 | Server |
> |------|------|--------|
> | 原神 (gs) | 1-5 | `cn_gf01`（官方服） |
> | 原神 (gs) | 6-9 | `cn_qd01`（B服） |
> | 原神 (gs) | 8（9位UID） | `os_usa`（美服） |
> | 原神 (gs) | 18（9位） | `os_euro`（欧服） |
> | 原神 (gs) | 8（以8开头9位） | `os_asia`（亚服） |
> | 原神 (gs) | 8（以8开头9位） | `os_cht`（台港澳） |
> | 星铁 (sr) | 1-5 | `prod_gf_cn` |
> | 星铁 (sr) | 6 | `prod_qd_cn` |
> | 绝区零 (zzz) | 10 | `prod_gf_cn` |
> | 绝区零 (zzz) | 15 | `prod_qd_cn` |
>
> 包含 `cn_` 或 `_cn` 的 server 使用国内 API 域名（`api-takumi.mihoyo.com`），否则使用海外域名（`sg-public-api.hoyolab.com` 等）。

#### GT-Manual 手动打码服务

- Express 服务，`Cfg.startGT()` 随插件启动（`startApi: true` 且 `Port`、`Address` 已配置时）
- `Port` 为监听端口，`bindHost` 为监听地址（默认 `127.0.0.1`，需反向代理时改 `0.0.0.0`）
- `Address` 为发送给用户的链接前缀（须用户设备可访问）
- `verifyAddr` 为 Bot 内部提交验证码的地址，本地部署填 `http://127.0.0.1:端口/GTest/register`
- 路由：`/GTest/register`（注册验证）→ `/GTest/:key`（浏览器页面）→ `/GTest/validate/:key`（提交/轮询结果）
- 外部静态资源来自 `https://img-hut.top/gt/`，本地 `express.static` 已禁用（全项目目录暴露风险）
- `Manual_geetest()` 通过 `Cfg.api` 读取配置（非 `Cfg.getConfig('api')`），与运行时配置一致

#### 配置结构（config.yaml `api:` 段）

```yaml
type: 1              # 0=test_nine, 1=ttocr.com, 2=2captcha.com
api:                 # 求解 API URL / test_nine 本地服务地址
resapi:              # 结果轮询 API URL（ttocr、2captcha）
key:                 # API Key（ttocr、2captcha）
query:               # 求解接口额外参数（ttocr、2captcha）
resquery:            # 结果接口额外参数（仅 2captcha）
startApi: false      # 是否启动内置 GT-Manual 打码服务
Port: 3000           # GT-Manual 监听端口
bindHost: 127.0.0.1  # 监听地址，本地 127.0.0.1，反向代理时 0.0.0.0
Address: http://...  # 发送给用户的打码链接前缀（须用户设备可访问）
verifyAddr: http://.../GTest/register  # Bot 提交验证码的地址
GtestType: 2         # 0=仅手动, 1=仅自动, 2=自动优先失败后手动
```

> `defSet/config.yaml` 中对应字段为 `${api_type}`, `${api_api}` 等占位符。

### 4. test_nine — 本地 AI 过码（子模块）

- 路径：`tool/test_nine/test_nine/`（git 子模块，指向 `https://github.com/luguoyixiazi/test_nine`）
- 独立 Python FastAPI 服务，不随云崽生命周期，可在 MCSM/Docker 上独立运行
- 模型文件（5 个 ONNX）需下载至 `tool/test_nine/test_nine/model/`，地址见 `tool/test_nine/README.md`
- 启动后配置 `type: 0`，`api` 填 `http://127.0.0.1:9645/pass_uni`
- 插件侧通过 `apiTool.js` 的 `test_nine` 条目发 GET 请求，不直接依赖 Python 进程
