# 模块：终局挑战与排行榜

本文件是 Axiu-Plugin 的详细文档。**规范与铁律在仓库根 `AGENTS.md`**（约定、配置写入口径、测试约定）；这里放事实与实现细节，改对应模块前按需阅读。

### 9. challenge — 星铁终局挑战 & 排行榜

终局挑战查询（末日幻影/虚构叙事/忘却之庭/异相仲裁） + 群排行。

**文件**：

| 文件 | 职责 |
|------|------|
| `apps/challenge.js` | 命令入口，6 条查询 + 3 条排行 rule |
| `model/srChallengeRank.js` | 排行存储模型（Redis ZSET 综合排序、赛季元信息、UID 身份） |
| `modules/challenge/srQuery.js` | 查询编排（末日/虚构/忘却/仲裁） |
| `modules/challenge/srRank.js` | 排行业务逻辑（buildSrCols） |
| `resources/challenge/SR/rank.html` | 排行 HTML 模板（art-template） |
| `resources/challenge/SR/rank.css` | 排行样式 |
| `guoba/challenge.js` | 锅巴 schema（原神 + 星铁挑战 + 排行开关） |

**排行设计**：

- **上报**：群聊中查询挑战数据（详细 API 成功）时，`_reportRanking` 解析最深层（`floors[0]`，楼层难→易排列）的本层数据写入 Redis ZSET；`srChallengeRank.enabled=false`（总开关）或该群群开关关闭时不参与上报
- **赛季**：从 API 原始 `schedule_id` 提取赛季标识，赛季名称从 Atlas-Plugin nanoka 图鉴按 periodNumber 查找
- **名次**：**名次键**（忘却 层→星→轮，末日 难度→分，虚构 层→星→分→轮，仲裁 绝境→王棋→骑士→轮）混合进制编码后存入 `__` 维度的 ZSET；**同码即并列**，共用密集名次（1,1,2），组内按**首查**先后
- **指定维度**：用户可指定单维度（如 `*忘却排名 星数`），支持全称别名
- **展示**：每行 QQ 头像（`e.group.pickMember(qq).getAvatarUrl()` → fallback qlogo URL） + 昵称/UID + 多列数值
- **TTL**：所有排行 key 90 天自动过期
- **并发安全**：同一 uid 的 UID 元信息「读-改-写」按 `uidKey` 串行化（`components/asyncLock.js` 的 `withKeyLock`），`*深渊` 并发查询三种挑战不再互相覆盖明细；上报与重置共用一把**按玩法**（=`challengeType`）的重置锁（`Axiu:challenge:rank:lock:reset:{type}`），`report()` / `resetRank()` 整体入锁，两把锁的获取顺序固定为 **resetLock → uidLock**
- **重置范围**：指定类型重置时只清理该类型的 ZSET 与赛季元信息，UID 元信息按类型修剪槽位（其他类型明细保留）；不指定类型才整键清理

**Redis 键**（全局排行，跨群共享）：

| 键 | 类型 | 内容 |
|----|------|------|
| `Axiu:challenge:rank:{type}:{dim}:{scheduleId}` | ZSET | member=uid, score=分数（`'__'` 为名次键编码） |
| `Axiu:challenge:rank:current:{type}` | String | 当前赛季 scheduleId（全局） |
| `Axiu:challenge:rank:season:{type}:{scheduleId}` | String | 赛季 JSON（scheduleName/beginTime/endTime/periodNumber） |
| `Axiu:challenge:rank:uid:{uid}` | String | UID 元信息 JSON（qq/scores/extra/scheduleId） |
| `Axiu:challenge:rank:{group}:cfg` | String | 群开关 JSON `{"status":1}` |

**维度定义**：

| 类型 | 维度 | 默认综合排序 | 显示列 |
|------|------|-------------|--------|
| 0 末日 | star/score/battle/round | 难度→分 | 难度/★/分 |
| 1 虚构 | star/score/battle/round | 层→星→分→轮 | 层/★/分/轮 |
| 2 忘却 | star/round/battle/floor | 层→星→轮 | 层/★/轮 |
| 3 仲裁 | boss/mob/round/hard | 绝境→王棋→骑士→轮 | 模式/王棋/骑士/轮(王棋\|骑士) |

**名次键与编码**（`rankKeyScore`）：

- 混合进制折叠：`value = value × (该级上界 + 1) + 该级值`，每级块宽 = 上界 + 1（上界见 `RANK_KEY_CAPS`）。
  块宽 > 该级以下所有取值之和，所以低级分数永远翻不到高级之上。旧的 `score×10` 在分数 ≥ 10000 时会顶掉星数位，就是块宽不够的例子（本轮一并修掉）。
- `round`（轮数）在 `scores` 里存**负值**（轮数越少越好），编码时加 `round` 上界还原成非负数。
- **战斗次数不进名次键**（只展示）：它会随重复挑战增长，进名次会让排名往回走。
- **首查时间不进分数、不展示**：只在**并列**（同名次键）时决定先后；`slot.firstTime` = 该期第一次观测到成绩的时刻，**落定后不刷新**；老数据没有 `firstTime` 的排在同名次末尾。
- **名次键取本期最优**（只升不降），只展示的字段取最后一次观测。

**跨插件依赖**：赛季名称从 `Atlas-Plugin/tool/nanoka-atlas-backend/.../星铁/{typeDir}/未分类/` 读取，按 `meta.recordId` 排序后取 `periodNumber-1` 位置的 `content.list.zh`。缺失 Atlas-Plugin 时返回空字符串。

### 10. 原神终局挑战 & 排行榜

原神终局挑战查询（深境螺旋/幻想真境剧诗/幽境危战）+ 群排行。

**文件**：

| 文件 | 职责 |
|------|------|
| `apps/challenge.js` | 命令入口，8 条查询 + 3 条排行 rule |
| `model/gsChallengeRank.js` | 排行存储模型（Redis ZSET 综合排序、赛季元信息、UID 身份） |
| `modules/challenge/gsQuery.js` | 查询编排 + HTML 渲染（buildAbyssData/buildRoleData/buildHardData），深渊仅返回最高层 |
| `modules/challenge/gsRank.js` | 排行业务逻辑（buildGsCols、resolveGsType） |
| `resources/challenge/GS/*.html/css` | 排行 + 查询模板（rank/abyss/role/hard） |
| `resources/challenge/GS/images/` | 图片资源（bg.jpg / medal*.png / star.png / nomedal.png） |
| `guoba/challenge.js` | 锅巴 schema（原神 + 星铁挑战 + 排行开关） |

**类型**：

| type | 名称 | 别名 | 查询命令 | 排行命令 |
|------|------|------|---------|---------|
| 0 | 深境螺旋 | #深渊 | `#深渊` / `#最新深渊` | `#深渊排行` |
| 1 | 幻想真境剧诗 | #剧诗 | `#剧诗` | `#剧诗排行` |
| 2 | 幽境危战·单人 | #危战 | `#危战` / `#单人危战` | `#危战排行` |
| 3 | 幽境危战·多人 | #危战多 | `#多人危战` / `#组队危战` | `#多人危战排行` |

**排行设计**：

- **上报**：群聊中查询挑战数据（API 成功）时自动上报到 Redis ZSET。危战单人(2)和多人(3)串行上报，避免 Redis 竞态覆盖；`gsAbyssRank.enabled=false`（总开关，`reportGsIfEnabled` 前置判定）或该群群开关关闭时不参与上报
- **赛季**：从 API `schedule_id` 提取赛季标识。深境螺旋的赛季名从 nanoka 图鉴按时间范围匹配 blessing 名称（如"冰迸之月"）
- **期数**：各类型独立 epoch 计算（深渊 2020-09-28 起 15天/期，剧诗 2024-07-01 起 30天/期，危战不显示期数）
- **名次**：**名次键**（见下表）混合进制编码后存入 `__` 维度的 ZSET；**同码即并列**，共用密集名次（1,1,2），组内按**首查**先后
- **展示**：每行 QQ 头像 + 昵称/UID + 多列数值；危战排行徽章列显示勋章图片
- **并发安全**：UID 元信息「读-改-写」按 `uidKey` 串行化（`components/asyncLock.js` 的 `withKeyLock`），并发上报不再互相覆盖明细；上报与重置共用一把**按玩法**（=`_baseType(type)`，危战单/多人同一把）的重置锁（`Axiu:gsAbyss:rank:lock:reset:{baseType}`），`report()` / `resetRank()` 整体入锁，两把锁的获取顺序固定为 **resetLock → uidLock**（只按 uid 锁管不到 ZSET 与重置的删键）
- **重置范围**：定向重置按真实 type 清 ZSET、按 base type 清赛季键与 current 指针（危战单/多人共用一套赛季键，重置其一会一并清除，下次上报重建），UID 元信息仅修剪目标类型槽位
- **改排序口径需重排**：编码值是写进 ZSET 的，口径调整后既有分数仍是旧编码，须执行 `#刷新…排行`（`rebuildAll` 用 UID 元信息里的 `scores` 重算名次键；首查不参与编码）

**数据流**：

```
用户 #深渊 / #剧诗 / #危战
  → getGsUserAuth(e) → MysApi(uid, ck, {game:'gs', log:false})
  → MysApi.getData('spiralAbyss' / 'role_combat' / 'hard_challenge')
  → checkGsCode() → 遇 1034/10035 调用 handler 过码
  → GsChallengeRank.report() 上报排行
  → buildAbyssData / buildRoleData / buildHardData 数据变换
  → render('challenge/GS', tplName, data) → reply(img)
  → return true（阻断 miao-plugin 重复调用）
```

**维度定义**（GS 排行）：

| 类型 | 名次键（决定名次） | 编码 | 显示列 |
|------|------------------|------|--------|
| 0 深渊 | 层 → 星 | `floor*100 + star` | 层 / ★ / 战斗 |
| 1 剧诗 | 模式 → 幕 → 星章 → 用时（少） | `((mode*1000 + floor)*100 + flower)*1e6 + (999999-用时)` | 模式 / 幕 / 星章 / 用时 / 借出 |
| 2/3 危战 | 难度 → 用时（少） | `difficulty*1e6 + (999999-用时)` | 难度 / 用时(秒) / 徽章(图片) |

- **首查不展示、不进分数**：只在并列（同名次键）时决定先后；`slot.firstTime` = 该期第一次观测到成绩的时刻，**落定后不刷新**（成绩提升也不改）
- **名次键取本期最优**：更差的上报不覆盖名次键，但会刷新只展示的字段（战斗 / 借出）——展示字段取**最后一次观测**
- **并列**：同编码 ⇒ 同密集名次（1,1,2），组内早首查者在前；本人名次按「严格更好的不同编码个数 + 1」算，因此并列者与列表同名次
- **单维度视图**（`#深渊排名 星数` 之类）仍按该列原始值排序，同样按同值并列

**角色头像**（查询模板用）：

`buildAvatarsMap(ids, infoMap)` 通过 miao-plugin 的 `MiaoCharacter.get(id)` 获取角色信息，读取本地 `face.webp` 为 base64 data URI（避免 Chromium file:// 限制），fallback 到 Enka CDN。返回 `{id, name, face, gacha, star, elem, level, cons}`。

**跨插件依赖**：
- `miao-plugin` — `MiaoCharacter` 模型获取角色名/头像/立绘
- `genshin` — `MysInfo.getUid(e, true)` 获取 UID，`mysApi.getData()` API 调用
- `Atlas-Plugin` — nanoka 图鉴数据（深境螺旋 blessing 名称），缺失时返回空

**配置**：`config/config.yaml` → `gsAbyss:` / `gsAbyssRank:` 段；`gsAbyssRank.enabled=false` 时不参与上报（也不再响应排行命令），星铁侧同名开关为 `srChallengeRank.enabled=false`

**资源文件**：
- 模板继承 `defaultLayout`，通过 `_res_path` 访问 Axiu 资源目录
- 深渊/剧诗/危战模板均使用头像叠层（`.abyss-avatar` / `.role-avatar` / `.hard-avatar`），头像左下角叠加 `Lv + 角色名` 合并标签；不再使用 avatar-card include
- 剧诗额外有角色统计卡行：最高伤害输出/击败最多敌人/最高承受伤害（正脸水印），最快完成演出队伍（API 全身侧图无框排列）
- 危战额外在头像右上角显示命座徽章（`avatar.rank`，仅危战 API 提供）
- 幽境危战模板各房间配置：4 人一队不折行延伸到中线（`.chall-left` 与 `.chall-info` 左右分布，`.chall-team` 无 `flex-wrap`）；右栏统计卡左右分布（最强一击/最高总伤害，角色正脸水印叠层 + dps 原始数值）；boss 图片在队伍下方（160px，等级叠左下角），关卡描述紧贴右侧
- 角色统计卡数据来源：`detail.fight_statisic`（`max_damage_avatar`/`max_defeat_avatar`/`max_take_damage_avatar`/`shortest_avatar_list`）
- 深渊查询只显示最高层数据，星星使用 `images/star.png` 图标
- 所有图片资源统一放在 `images/` 子目录（bg.jpg / medal*.png / star.png / nomedal.png）
- render.js 设置 `data.element = 'sr'` 避免 common.css 元素背景干扰 GS 模板
