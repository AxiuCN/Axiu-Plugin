# 模块：扫码登录与抽卡记录

本文件是 Axiu-Plugin 的详细文档。**规范与铁律在仓库根 `AGENTS.md`**（约定、配置写入口径、测试约定）；这里放事实与实现细节，改对应模块前按需阅读。

### 5. qrLogin — 扫码登录 / 刷新CK

从 xiaoyao-cvs-plugin 移植，两个命令共享同一组 model 层（`passportApi` → `passportTool` + `passportUtils` → `stokenStore` → `qrUser` → `qrLogin`）。
> **注**：`#更新抽卡记录` 已迁移至 `apps/gsGachaLog.js`（原神）/ `apps/srGachaLog.js`（星铁）。

> **注意**：代码中 `rule[].permission` 为 `'all'`，但 README 和注释标注"仅 master 可用"。这依赖外部权限控制（如 group.yaml 的 `onlyReplyAt` 或黑白名单），非代码层限制。

**命令 1: #扫码登录**
```
用户 #扫码登录
  → QrLogin.qrCodeLogin() → passportApi qrCodeLogin → 返回 {url, ticket}
  → renderImg('qrCode/index', {url}) → puppeteer 截图 QR 码 HTML 页面
  → QrLogin.GetQrCode(ticket) → 轮询 passportApi qrCodeQuery（5s×60次）
  → 确认后返回 {cookie, stoken}
  → _bindSkCK(e, loginRes):
      1. _bindStoken(e, loginRes) → bbsGetCookie → seachUid 保存 stoken
      2. userck.bing() 自动绑定 CK 到 cookie 池（无需手动 #刷新ck）
  → 绑定阶段提示（seachUid + bing 的全部 reply）收集合并为一条转发消息
  → 转发 node 匿名（不携带机器人昵称），头部固定插入「*扫码登录成功，Bot大部分功能已开放*」
```
> 对齐逍遥 `bindSkCK` 模式：扫码成功后 stoken + CK 一步绑定，用户无需额外操作。
> **合并转发**：`_bindSkCK` 拦截绑定阶段 reply → `makeForwardMsg`，node 仅 `{message}`（OneBotv11 适配器回退为「匿名消息」），避免扫码后连环刷屏。
> **安全**：`GetQrCode` 轮询中的 `logger.mark` 已脱敏，仅记录状态和 user_id，不记录含 stoken/cookie 的完整 API 响应。

**命令 2: #刷新ck**（仅 master）
```
用户 #刷新ck
  → stokenStore.getUserStoken() → 读取已绑定的 stoken
  → 逐条调 passportApi bbsGetCookie → 获取新 cookie_token
  → V3: 委托 genshin 插件 userck.bing() 绑定到 cookie 系统
  → 多账号结果收集合并为一条转发消息（node 匿名，不携带机器人昵称）
```

**model 层依赖**：
```
apps/qrLogin.js
  → model/qrLogin.js      QR 登录编排（qrCodeLogin、GetQrCode、pickToken）
  → model/qrUser.js       用户模型（getData、cookie、stoken、seachUid、getRefreshedCookieAndStoken）
  → model/stokenStore.js  持久化（getUserStoken、getBingStoken、saveBingStoken、getBingCookie）
  → model/mys/passportApi.js    HTTP 客户端（11个端点、DS签名、pass/bbs/stoken/authKey header）
  → model/mys/passportTool.js   常量（盐值、BaseURL、RSA公钥、APP_VERSION）
  → model/mys/passportUtils.js  工具（sleepAsync、randomString、getCookieMap、getServer）
  → components/render.js        HTML 渲染（puppeteer 截图）
  → resources/qrCode/           QR 码模板（index.html + jquery.qrcode.js）
```

**配置**：`api.qrLogin_enabled`（锅巴 Switch 开关），默认 true。

**stoken 存储**：`plugins/Axiu-Plugin/data/stoken/{userId}.yaml`，格式 `{uid: {stuid, stoken, ltoken, mid, uid, userId, ...}}`。`saveBingStoken` 按游戏 UID 作顶层键、同账号多游戏角色**对象合并保存**（`Object.assign` 后整体序列化，非字符串拼接）。

> **stokenStore 双路径数据源**：
> - `getBingStoken()` → `plugins/Axiu-Plugin/data/stoken/{userId}.yaml` — 扫码登录绑定的 stoken（自有数据）
> - `getBingCookie()` → `data/MysCookie/{userId}.yaml` — 读取 genshin 插件的 CK 文件，用作 stoken 查找回退

> **passportApi 构造兜底**：`new PassportApi(e)` 按 `ck[e.uid]`（游戏 UID 键）取 stoken，未命中时从 `e.cookie` 提取 `ltuid` 关联文件条目（stoken 为账号级凭证，同 stuid 各游戏角色通用）——覆盖 stoken 文件缺个别游戏 UID 键的场景（如 `#更新抽卡记录` authkey 获取）。

### 6. gachaLog — 抽卡记录管理（原神 gsGachaLog / 星铁 srGachaLog）

整合 Mihoyo 官方 API 和提瓦特小助手（天如移植）两种抽卡记录获取方式，共用 genshin 插件的 GachaLog JSON 存储（原神 `data/gachaJson/{qq}/{type}.json`、星铁 `data/srJson/{qq}/{uid}/{type}.json`）。

**命令入口**：

| 文件 | 命令 | 功能 |
|------|------|------|
| `apps/gsGachaLog.js` | `#更新抽卡记录` / `#更新小助手抽卡记录 [链接]` / `#获取抽卡链接`（仅私聊） | 原神抽卡 |
| `apps/srGachaLog.js` | `*更新星铁抽卡记录` / `#星铁更新抽卡记录` / `*获取星铁抽卡链接`（提示不可用） | 星铁抽卡 |

两个入口均使用独立 5 分钟 Redis 频率锁（`Axiu-Plugin:gachaLog:update/assistant/getUrl:{user_id}` 与 `:sr:update/:sr:getUrl`）；锁/UID 查找抽到 `components/gachaUtils.js` 共用。

**原神三个命令**：

| 命令 | 正则 | 功能 | 私聊限制 |
|------|------|------|---------|
| `#更新抽卡记录` | `^#更新抽卡记录$` | Mihoyo 官方 API（增量更新，仅最近 6 个月） | 无 |
| `#更新小助手抽卡记录 [链接]` | `^#?(获取\|更新)(提瓦特)?小助手(抽卡\|祈愿)?(记录\|历史)` | lelaer.com 全历史 UIGF 导入 | 无 |
| `#获取抽卡链接` | `^#获取抽卡链接$` | stoken→authkey→返回米游社抽卡 URL | **仅私聊** |

**星铁两个命令**（官方抽卡小程序接口同步：badge login + rpg_gacha_record，参考荷花重制版；星铁外部 authkey 不可用，不走 authkey 全线）：

| 命令 | 正则 | 功能 |
|------|------|------|
| `*更新星铁抽卡记录` | `^#星铁(更新)?(星铁)?(抽卡\|祈愿)?(记录\|历史)$` | cookie → badge login（e_hkrpg_token）→ 6 池 five_star_list/pool_stat → 镜像 genshin srJson（五星+垫抽+池统计） |
| `*获取星铁抽卡链接` | `^#星铁获取(星铁)?(抽卡\|祈愿)?链接$` | 提示星铁不支持外部 authkey，改用自动更新或手动导入 |

> 框架星铁前缀机制：`*更新星铁抽卡记录` 被 loader 标准化为 `#星铁更新星铁抽卡记录`，故 rule 正则以 `#星铁` 开头并允许「星铁」重复。查询/统计/渲染复用 genshin gcLog（`*角色记录`/`*光锥记录`/`*全部记录`/`*星铁统计`）。

**数据完整度**：官方小程序接口仅五星列表 + 垫抽 + 池统计（无每抽明细）；`buildMiaoPoolRecords` 构造「五星 + 占位补抽数」近似序列写入 `data/srJson/{qq}/{uid}/{11|12|21|22|1|2}.json`（含历史去重、平铺兼容），`*角色记录`/统计可见五星与垫抽，`*全部记录`/`*导出记录` 含占位条目；每抽全量需手动粘贴游戏内星铁链接走 genshin 导入。**已有真实数据时不覆盖、改为追加**：若该池已有导入的真实数据（存在真实名字的 3/4 星记录，非本插件 `name='占位记录'` 占位），走 `appendNewRecordsToGenuinePool` —— 在原数据的时间更新方向（genshin 写入约定为新在前，亦兼容旧在前）追加「新增五星（时间晚于原数据最新五星，且「名称+时间」未出现）+ 其间隔占位 + 当前垫抽占位」，原记录逐条保留；`pools[].merged=true/added=N` 表示已追加，`kept=true` 表示已有数据无新增。时间推导统一按 UTC+8（`deriveTimeFromId`，米游社 time/id 均为本地时间），避免与导入数据相差 8 小时导致漏判新五星。**新增五星的扣减口径**：按「该五星与上一个五星之间的间隔」扣除本地已记录抽数——上一个五星优先取更旧的下一个接口候选，没有则取本地最新五星，两者都没有（该池首次出五星）则以「早于该五星」为界；记录先后用数组顺序 + 同源数字 id 判定（抽卡 id 为 19 位，不能用 `Number` 相减比较），因此十连同秒的多条记录不会被误判成「未记录」而重复补数。

**绑定/引导提示约定**：抽卡相关提示涉及「未绑定 / 账号不对」一律引导 `#扫码登录`（Axiu 自有绑定入口），**禁止**引导 `*绑定uid` 或类似不存在的命令；未找到 UID 时提示「请先发送【#扫码登录】绑定星铁账号后重试，或在消息中附带星铁UID」。

**authkey 获取优先级**（`components/gachaUtils.js` `getAuthKey`，统一使用 Axiu 自有 QrUser，不依赖 xiaoyao-cvs-plugin）：
1. QrUser.getData('authKey') — stoken→passportApi genAuthKey（`authKey` 端点 game_biz 参数化：原神 `hk4e_cn` / 星铁 `hkrpg_cn`，uid/region 由调用方传入）
2. Redis 缓存（`Yz:genshin:gacha:url:{uid}`，之前 URL 提交过的）
3. 提示用户发送抽卡链接（setContext('logUrl') 两步交互，原神路径）

> passportApi `authKey` 端点（`model/mys/passportApi.js`）body：`game_biz: data.gameBiz ?? (isOs ? 'hk4e_global' : 'hk4e_cn')`、`game_uid: (data.uid ?? e.uid) * 1`、`region: data.region ?? e.region`——原神路径返回值不变，星铁传 `hkrpg_cn`。
> 星铁 region 由 `passportUtils.getSrServer(uid)`（UID 前缀 → `prod_gf_cn`/`prod_qd_cn`/`prod_official_*`）提供。

### 7. 星铁 CK 自动刷新（Axiu 自实现，独立于 genshin）

> 原 `apps/ckAutoRefresh.js`（genshin/miao 猴子补丁自动刷新）已移除，移交 genshin 插件原生维护；原神 API 路径（含终局挑战 gsQuery）由 genshin 处理 10001。星铁因 `MysSrApi` 自实现 HTTP 层绕开 genshin 补丁，自动刷新在 Axiu 内自实现。

- 位置：`model/mys/mysSrApi.js`（`_findStokenByLtuid` / `_doRefreshCk` / `_refreshCkAndRetry`）
- 触发：`MysSrApi.checkCode` 遇 `retcode=10001` 且 message 含 `登录/login`
- 流程：cookie 提取 ltuid → 遍历 `data/stoken/*.yaml` 匹配 stuid → `_refreshLocks` 互斥锁 → `bbsGetCookie` 换 cookie_token → `MysUser.setCkData + save()` 更新账号级 ck（**不调用 bing()，不修改 QQ↔账号 归属**）→ 新 cookie 重试原请求
- 失败：无匹配 stoken 或刷新失败 → 提示「cookie已失效 / sk已失效，请重新扫码登录」，返回原始 10001 走 simpleRes 降级
- 并发：`Map<ltuid, Promise>`，首个请求刷新、其余等待；`finally` 删锁防死锁
- 归属安全：刷新对齐 genshin `ckRefresh` 仅更账号级 ck，阻断「刷新把账号挂到与查询无关用户」的双归属增殖
- 请求超时：普通请求与设备指纹（`_getDeviceFp` 的指纹请求）、设备注册（`deviceLogin` / `saveDevice`）统一走 `AbortSignal.timeout(REQUEST_TIMEOUT_MS)`（10s）——辅助请求原先无 signal，冷缓存或指纹接口慢响应会把整轮查询拖住；指纹失败仍走兜底值、设备注册失败仍容错
