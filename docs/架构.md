# 架构与项目结构

本文件是 Axiu-Plugin 的详细文档。**规范与铁律在仓库根 `AGENTS.md`**（约定、配置写入口径、测试约定）；这里放事实与实现细节，改对应模块前按需阅读。

### 跨插件硬依赖

以下模块对 genshin 插件（及 miao-plugin）有深层 import，缺失时对应功能降级（不会阻止插件加载）：

| 文件 | 依赖路径 | 用途 |
|------|---------|------|
| `qrLogin.js` | `../../../plugins/genshin/model/user.js` | `userck.bing()` 绑定 CK 到 V3 系统 |
| `gsGachaLog.js` / `srGachaLog.js` | `../../genshin/model/gachaLog.js` | `GachaLog.logUrl()` 拉取抽卡记录 + dealUrl/checkUrl 解析链接 + readJson/writeJson 本地存储 |
| `gsGachaLog.js` / `srGachaLog.js` | `../../genshin/model/mys/NoteUser.js` | UID 查找回退（无 runtime 绑定时） |
| `stokenStore.js` | `./data/MysCookie/${userId}.yaml` | 读取 genshin 插件的 CK 文件作为 stoken 查找回退 |

**配置文件路径**：

| 配置 | 运行时 | 模板/参考 |
|------|--------|----------|
| 过码 API | `config/config.yaml` → `api:` 段 | `defSet/config.yaml`（锅巴模板） / `config/config.yaml.example`（手动参考） |
| 入群审核 | `config/group_config.yaml` | `defSet/group_config.yaml` / `config/group_config.yaml.example` |
| 签到主配置 | `config/config.yaml` → `signin:` 段 | `defSet/config.yaml`（锅巴模板） / `config/config.yaml.example`（手动参考） |
| 签到模板 | `config/MihoyoBBSTools_config.yaml` | `defSet/MihoyoBBSTools_config.yaml`（锅巴/刷新模板） / `config/MihoyoBBSTools_config.yaml.example`（手动参考） |
| 星铁终局挑战 | `config/config.yaml` → `srChallenge:` 段 | `defSet/config.yaml`（锅巴模板） / `config/config.yaml.example`（手动参考） |
| 星铁终局挑战排行 | `config/config.yaml` → `srChallengeRank:` 段 | 同上 |
| 原神终局挑战 | `config/config.yaml` → `gsAbyss:` / `gsAbyssRank:` 段 | `defSet/config.yaml`（锅巴模板） / `config/config.yaml.example`（手动参考） |
| 代发言 | `config/config.yaml` → `proxySpeak:` 段 | `defSet/config.yaml`（锅巴模板） / `config/config.yaml.example`（手动参考） |

**添加新功能最小步骤**：`apps/` 下新建 `.js` → export 继承 `plugin` 的 class → 重启即可（`index.js` 自动发现）。


### 初始化提示

新会话开始时，按以下步骤快速进入工作状态：

1. `git log --oneline -5` — 确认当前分支和最近提交
2. 回顾「框架全局依赖」表 — Bot 方法、logger、redis、segment 等全局变量
3. 阅读对应功能模块章节 — 了解事件注册方式（`accept` / `rule` / `handler`）和配置结构
4. 注意入口机制：`index.js` 使用 `Promise.allSettled` 动态 import `apps/*.js`，新增文件无需修改入口
5. 在开发机编辑 → 跑回归套件 → 验证用的临时日志一律还原 → 由部署方同步到运行实例（盘符映射与实例路径见 `docs/private/部署环境.md`，**该目录不入库**）

## 框架全局依赖

以下变量由 Yunzai 框架注入，插件直接使用，无需 require/import：

| 变量 | 说明 |
|------|------|
| `Bot` | Yunzai 实例，含 `Bot.uin`、`Bot.pickGroup()`、`Bot.pickMember()` |
| `logger` | 日志对象，`logger.info` / `logger.warn` / `logger.error` / `logger.mark` / `logger.debug` |
| `redis` | Redis 客户端，`redis.get` / `redis.set` / `redis.setEx` / `redis.del` |
| `segment` | oicq 消息段构造器，`segment.at()` / `segment.reply()` |
| `_` (lodash) | `_.sample` / `_.sampleSize` / `_.trim` / `_.isEqual`（model 层使用） |
| `md5` | MD5 哈希函数（mysApi.js DS签名） |
| `crypto` | Node.js crypto 模块（`crypto.randomUUID()`） |


## 架构

### 数据流

```
用户消息/事件 → apps/（事件绑定+配置加载）→ modules/（业务编排）→ model/（HTTP API）→ 结果
```

### 分层职责

| 层 | 职责 |
|----|------|
| `apps/` | 事件绑定、委托调用 |
| `modules/` | 业务编排、流程控制 |
| `model/` | 外部 HTTP API、配置管理 |
| `components/` | 配置加载、常量、工具 |

> **model 层循环依赖**：`mysApi.js:144` 调用 `getDeviceFp.Fp()` 获取设备指纹，`getDeviceFp.js:7` 创建 `new MysApi()` 调 `getUrl('getFp')` 构造请求。依赖通过静态方法调用（`getDeviceFp.Fp()` 不实例化 `getDeviceFp`）和函数内延迟实例化解开，非构造函数循环。

### 入口加载机制（index.js）

1. `import gsCfg from './model/gsCfg.js'` → `gsCfg.copyPath()` 复制 defSet→config → `gsCfg.startGT()` 启动手动打码服务
2. `Promise.allSettled` 动态 import `apps/` 下所有 `.js` 文件
3. 单个 app 加载失败不影响其他模块
4. 加载结果存入 `export { apps }`
