# 模块：米游社签到（mysSignin）

本文件是 Axiu-Plugin 的详细文档。**规范与铁律在仓库根 `AGENTS.md`**（约定、配置写入口径、测试约定）；这里放事实与实现细节，改对应模块前按需阅读。

### 8. mysSignin — 米游社签到

基于 MihoyoBBSTools（Python，git 子模块）的社区+游戏签到。

- 注册方式：`event: 'message'` + `rule[]` 命令 + `task[]` 定时任务
- Python 桥接脚本：`tool/MihoyoBBSTools/mysSignin_runner.py`（替换 `sys.modules["captcha"]` 实现过码桥接）
- 用户配置：`tool/MihoyoBBSTools/MihoyoBBSTools/config/{qq}_n.yaml`（n 从 1 递增，支持多账号）
- 用户 ID 兼容 QQ 与非数字平台 ID（微信等，形式不固定）：批量遍历用 `/^(.+)_(\d+)\.yaml$/`（前缀贪心）识别，`listUserConfigs` 对 userId 做正则转义；报告 `@` 仅对纯数字 ID 且群成员生效，其余回落 `用户:{id}` 文本
- 模板配置：`config/MihoyoBBSTools_config.yaml`（运行时，从 `.example` 复制）

**命令**：

| 命令 | 方法 | 权限 | 说明 |
|------|------|------|------|
| `#初始化签到环境` | `initEnv` | master | 检查 Python、pip install 依赖、拉取子模块（仅 MihoyoBBSTools） |
| `#注册自动签到` | `register` | all | 用 stoken 换 cookie，按 stuid 去重生成 `{qq}_n.yaml` |
| `#注册本群签到` | `groupRegister` | master/admin | 为群内成员增量注册（已有账号更新/补新增，去重） |
| `#注册所有群签到` | `registerAllCmd` | master | 遍历机器人全部群的成员增量注册（与批量任务互斥） |
| `#签到名单列表` | `listProfiles` | master | 列出所有已注册用户及账号数（以合并转发发出；转发能力不可用时发纯文本） |
| `#签到` | `startSignin` | all | 执行当前用户所有 `_n.yaml` 的签到（兼容旧 `#开始签到`） |
| `#全部签到` | `signinAll` | master | 遍历所有注册用户（自动签到期间互斥） |
| `#刷新自动签到` | `refreshCookieCmd` | all | 用 stoken 刷新当前用户所有 `_n.yaml` 的 cookie |
| `#签到状态` | `signinStatus` | all | 查看绑定账号数及签到开关状态 |
| `#删除签到` | `deleteSigninCmd` | all | 删除当前用户所有签到配置（调用 `deleteUserConfigs`，需重新注册） |
| `#删除stoken` | `deleteStokenCmd` | all | 删除当前用户所有 stoken 条目，并一并删除该用户的签到配置（配置内含 cookie/stoken 明文副本），需重新扫码绑定并重新注册 |

**定时任务**（2 个）：
- 米游社自动刷新cookie（默认 `0 30 4 * * ? *`，从 `signin.refreshSchedule` 读取）— 遍历所有注册用户，用 stoken 刷新 cookie_token 并写回配置文件
- 米游社自动签到（默认 `0 0 5 * * ? *`，从 `signin.schedule` 读取）— 遍历所有注册用户执行签到，完成后向 master 和配置群聊发送汇总报告
- `task[].fnc` 必须是箭头函数引用（`() => this.xxx()`），不能是字符串。`loader.js:507` 调用 `i.fnc()` 而非 `plugin[i.fnc]()`

**签到日志**：Python 签到详细输出写入 `pluginRoot/log/signin-{date}.log`（`components/signinLogger.js`），保留 7 天自动清理。仅关键事件（开始/完成/失败/超时）进入云崽运行日志。

**通知**：`_sendReport(header, failedUsers)` 向 master 私聊 + `signin.reportGroups` 配置的群聊发送结构化报告（群内失败用户为纯数字 ID 且在群内时用 @，其余非数字 ID（微信等）显示 `用户:{id}` 文本；主人私聊一律 ID 文本；尾部动态版权行）。`_sendNotification(message)` 保留纯文本推送给定时刷新任务。汇总使用 `buildSigninReport`/`buildRefreshReport` 构建（统计头 + 失败用户分组）。刷新报告的**用户级口径分三档**：账号全部成功 / 部分成功 / 全部失败——**成功必须是「`ok` 为真且没有失败账号」**，`ok:false` 但失败明细为空的（未绑定 stoken、未注册签到）同样计入失败，否则「根本没刷新」会被算成全部成功（第四轮 #6）；部分成功的用户同样列出其失败账号（含「sk 已失效，已自动删除签到配置」与恢复步骤），避免「有账号成功」就把其余账号的失败吞掉。(GSelectGroup 组件)

**增量注册**：`registerUser` 为增量语义——stuid 已有配置 → `refreshUserConfigCookie` 原地更新；stuid 新增 → `getNextN` 新建；stoken 失效 → 删 stoken 条目 + 一并删除对应配置；已有配置 stuid 已不在 stoken → 残留清理。`registerGroupMembers`/`registerAllGroups` 复用同一增量逻辑（不再跳过已注册成员）。

**配置**：主配置 `config/config.yaml` → `signin:` 段（schedule、refreshSchedule、pythonCommand、reportGroups、captchaRetries 等）。模板配置 `config/MihoyoBBSTools_config.yaml`（游戏开关、BBS 任务开关），注册时复制给新用户。

**过码桥接**：Python `tool/MihoyoBBSTools/mysSignin_runner.py` 将 `sys.modules["captcha"]` 替换为文件 IPC 实现（`.request.json` / `.response.json`）。Node.js `CaptchaBridge` 轮询请求文件，调用 `loveMys` 现有求解链路（test_nine/ttocr/2captcha），写入响应。`signinManager` 外层控制重试（默认 3 次）。

**失效自动清理**：`refreshCookie`（bbsGetCookie）失败且命中 `/(登录|login)/` 错误时判定 stoken 失效——
- `registerUser`（注册签到）→ 自动删除 stoken 存储中该账号条目（同 stoken 多 uid 一并删），提示「已自动删除，请重新扫码绑定」
- `refreshUserCookies`（刷新签到/定时刷新）→ 自动删除对应签到配置文件 `{qq}_n.yaml`，提示「sk 已失效，已自动删除签到配置」
- 临时网络等非登录类错误不触发清理（避免误删）

**签到结果判定**：Python 依赖在失败分支（如 HTTP 429 重试失败）只把失败说明写进结果文本，`status_code` 仍为 0，因此不能只凭状态码判定成功。`mysSignin_runner.py` 同时检查文本失败标记（`本次签到失败` / `脚本签到失败` / `脚本签到发生异常` / `token 失效`——后者覆盖云游戏 `-100` 的国服「token 失效/防沉迷」与国际服「云原神 token 失效」两套文案），命中即 `ok=false` 并回传 `failedMarks`（节点侧日志同步打印）。汇总 `buildSigninReport` 返回 `{header, failedUsers, successUsers}`——成功账号明细随主人私聊发送，群聊保持「统计头 + 失败用户」不变，避免刷屏。**遗留**：社区签到（`mihoyobbs.py`）失败只写 `log.error`、不进返回文本，无法用文本标记捕获。

> **命中标记只是「判失败」，凭据不会被自动清除**：依赖在 `-100` 分支里的清理动作（子模块 `config.py` 的 `clear_cookie_cloudgame_*`）在 serverless 模式下**提前返回**，而 `mysSignin_runner.py` 设了 `config.serverless = True`。所以云游戏 token 失效后要主人自己重新抓 token 并更新 `config/MihoyoBBSTools_config.yaml`，报告里不会出现「已自动删除」这类动作（独立运行依赖时才有删除行为）。
